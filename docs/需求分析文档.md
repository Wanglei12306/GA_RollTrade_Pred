# 基于遗传算法的量化策略分析系统需求分析文档

## 1. 引言

### 1.1 编写目的

本文档用于明确“基于遗传算法的量化策略分析系统”的项目目标、业务范围、功能需求、数据需求、非功能需求与验收标准，为后续系统设计、编码实现、测试和项目验收提供依据。

本系统面向股票与期货等金融量化交易场景，旨在通过多技术指标池、遗传算法优化、滚动窗口训练预测和回测分析，实现买卖时机的智能辅助判断，并通过 Web 页面展示行情数据、交易信号和回测结果。

### 1.2 项目背景

传统量化交易策略通常依赖人工选择少量技术指标和固定参数，存在市场适配性差、参数固化、策略僵化、容易过拟合、可能出现未来函数等问题。当市场风格发生变化时，固定策略往往难以及时调整。

为解决上述问题，本项目设计并实现一套基于遗传算法的多技术指标组合滚动交易时机预测系统。系统通过构建多类别技术指标候选池，利用遗传算法自动筛选有效指标、优化指标参数、分配指标权重，并结合滚动窗口训练机制，实现动态择时和标准化回测分析。

### 1.3 适用范围

本文档适用于本项目第一阶段需求分析、概要设计、编码实现和测试验收。系统第一版以课程实训可完成为目标，重点实现单标的历史数据导入、指标计算、遗传算法优化、滚动预测、回测分析和 Web 可视化展示。

### 1.4 术语说明

| 术语 | 说明 |
|---|---|
| K线数据 | 金融市场按时间周期记录的开盘价、最高价、最低价、收盘价、成交量等数据 |
| 技术指标 | 根据历史价格和成交量计算出的辅助分析指标，如 MA、MACD、RSI、BOLL 等 |
| 指标池 | 系统预置的多类技术指标及其多组参数候选集合 |
| 遗传算法 | 模拟自然选择和遗传机制的优化算法，包括选择、交叉、变异等过程 |
| 染色体 | 遗传算法中的个体编码，表示一套可执行的交易策略 |
| 适应度函数 | 用于评价策略优劣的综合评分函数 |
| 滚动窗口 | 按时间顺序不断向前移动的训练与预测机制 |
| 回测 | 使用历史数据验证交易策略表现的过程 |
| 最大回撤 | 资金净值从历史高点到后续低点的最大跌幅 |
| 夏普比率 | 衡量单位风险下超额收益能力的指标 |

## 2. 项目概述

### 2.1 系统目标

系统目标是实现一套 Java Web 端量化策略分析系统，能够完成以下任务：

1. 支持导入股票或期货历史 K 线数据。
2. 构建覆盖趋势、震荡、波动率、成交量、乖离率等维度的技术指标池。
3. 使用遗传算法自动完成指标筛选、参数寻优、权重分配和交易阈值优化。
4. 使用滚动窗口机制进行训练和外推预测，降低未来数据泄露和静态过拟合风险。
5. 根据优化后的策略生成买入、卖出和持仓信号。
6. 对策略进行标准化历史回测，输出收益、风险和交易统计结果。
7. 通过 Web 页面展示行情走势、指标曲线、买卖信号、资金曲线、回撤曲线和回测指标。

### 2.2 系统用户

| 用户角色 | 使用目标 |
|---|---|
| 普通用户/学生 | 上传行情数据，设置策略参数，运行回测，查看结果 |
| 策略研究人员 | 对比不同参数配置下的策略表现，分析指标组合效果 |
| 教师/评审人员 | 查看系统功能完整性、算法流程、回测结果和课程成果展示 |

### 2.3 系统边界

第一版系统主要关注历史数据分析与回测展示，不直接连接证券或期货实盘交易接口，不提供真实下单功能。系统输出的买卖信号仅用于策略研究、课程展示和历史验证，不构成投资建议。

## 3. 总体需求

### 3.1 总体业务流程

系统整体业务流程如下：

1. 用户进入 Web 系统。
2. 用户上传或选择股票/期货历史 K 线数据。
3. 系统完成数据解析、校验和预处理。
4. 用户配置遗传算法参数、滚动窗口参数和指标池范围。
5. 系统在训练窗口内运行遗传算法，生成最优策略。
6. 系统使用最优策略对未来测试窗口进行外推预测。
7. 系统滚动时间窗口，重复训练与预测过程。
8. 系统汇总所有测试窗口中的交易信号。
9. 系统执行回测，计算绩效指标。
10. 系统在 Web 页面展示图表、指标和交易记录。

### 3.2 系统架构要求

系统采用 Java Web 架构，建议基于 Spring Boot 实现，整体分为以下层次：

| 层次 | 主要职责 |
|---|---|
| 表现层 | 提供 Web 页面、参数配置表单、图表展示和结果查看 |
| 控制层 | 接收用户请求，调用业务服务，返回页面或接口数据 |
| 业务层 | 处理数据导入、指标计算、遗传算法、滚动预测和回测逻辑 |
| 模型层 | 定义 K 线数据、指标结果、染色体、交易信号、回测结果等对象 |
| 数据层 | 负责 CSV 文件读取、样例数据管理，后续可扩展数据库存储 |

### 3.3 技术路线要求

| 类型 | 技术选型 |
|---|---|
| 编程语言 | Java |
| Web 框架 | Spring Boot |
| 构建工具 | Maven |
| 页面模板 | Thymeleaf 或前后端接口页面 |
| 图表展示 | ECharts |
| 数据格式 | CSV |
| 数据处理 | Java 集合、Apache Commons CSV 等 |
| 数学计算 | 自定义计算逻辑或 Apache Commons Math |
| 部署方式 | 本地运行 Web 服务，通过浏览器访问 |

## 4. 功能需求

### 4.1 数据管理模块

#### 4.1.1 数据导入

系统应支持用户通过 Web 页面上传 CSV 格式的股票或期货历史 K 线数据。

CSV 数据至少应包含以下字段：

| 字段 | 说明 |
|---|---|
| date/time | 交易日期或交易时间 |
| open | 开盘价 |
| high | 最高价 |
| low | 最低价 |
| close | 收盘价 |
| volume | 成交量 |

#### 4.1.2 数据校验

系统应对上传数据进行基础校验：

- 检查必要字段是否存在。
- 检查价格和成交量是否为有效数值。
- 检查时间字段是否可解析。
- 检查数据是否按时间升序排列。
- 对缺失值、重复记录和异常值给出提示。

#### 4.1.3 数据预处理

系统应支持对原始行情数据进行预处理：

- 按时间排序。
- 去除明显无效记录。
- 对缺失数据进行提示或简单处理。
- 将 CSV 数据转换为系统内部 K 线数据对象。

### 4.2 技术指标池模块

#### 4.2.1 指标类型

系统应构建多维度技术指标池，至少支持以下指标：

| 指标 | 类型 | 说明 |
|---|---|---|
| MA | 趋势类 | 移动平均线 |
| MACD | 趋势/动量类 | 指数平滑异同移动平均线 |
| RSI | 震荡类 | 相对强弱指标 |
| BOLL | 波动类 | 布林带 |
| KDJ | 震荡类 | 随机指标 |
| ATR | 波动率类 | 平均真实波幅 |
| OBV | 成交量类 | 能量潮 |
| CCI | 乖离/顺势类 | 顺势指标 |

#### 4.2.2 参数候选集

系统应为各类指标配置多组参数候选，避免固定参数导致策略适配性不足。例如：

- MA：5日、10日、20日、60日。
- RSI：6日、12日、24日。
- BOLL：可配置中轨周期和标准差倍数。
- MACD：可配置快线周期、慢线周期和信号线周期。
- ATR、CCI、KDJ：配置多套常见参数方案。

#### 4.2.3 指标计算

系统应根据 K 线数据计算技术指标结果，并将指标值与时间序列对齐，为后续遗传算法优化和交易信号生成提供输入。

### 4.3 遗传算法优化模块

#### 4.3.1 染色体编码

系统应将每个遗传算法个体编码为一套完整交易策略，编码至少包含以下内容：

| 编码内容 | 说明 |
|---|---|
| 指标选择掩码 | 使用二进制或布尔数组表示是否启用某个指标 |
| 指标参数集合 | 表示各选中指标对应的参数组合 |
| 指标融合权重 | 表示不同指标信号在最终决策中的权重 |
| 多空交易阈值 | 表示买入、卖出或做多、做空信号触发条件 |

#### 4.3.2 种群初始化

系统应根据指标池随机生成初始种群，保证个体中包含有效指标组合、参数组合和权重配置。

#### 4.3.3 选择、交叉与变异

系统应实现遗传算法基本操作：

- 选择：优先保留适应度较高的策略个体。
- 交叉：在两个个体之间交换部分编码，生成新策略。
- 变异：随机调整指标选择、参数、权重或阈值，增加搜索多样性。

#### 4.3.4 适应度函数

系统应构建多维度综合适应度函数，不应仅以收益率作为唯一优化目标。适应度函数应综合考虑：

- 年化收益率。
- 最大回撤。
- 夏普比率。
- 交易胜率。
- 盈亏比。

适应度函数应鼓励收益稳定、风险可控、回撤较低、交易质量较高的策略，避免过度拟合历史局部行情。

### 4.4 滚动窗口训练与预测模块

#### 4.4.1 滚动窗口设置

系统应支持配置训练窗口和预测窗口。第一版默认采用：

- 训练窗口：连续 3 个月历史数据。
- 预测窗口：未来 1 个月数据。
- 滚动步长：1 个月。

#### 4.4.2 训练与外推预测

系统应在每轮滚动过程中执行以下逻辑：

1. 使用当前训练窗口数据运行遗传算法。
2. 得到当前窗口下的最优策略。
3. 使用该策略对后续预测窗口进行外推预测。
4. 生成预测窗口内的买卖点和持仓状态。
5. 将窗口向前滚动，进入下一轮训练与预测。

#### 4.4.3 时序隔离要求

系统必须保证训练集和测试集严格按时间切分。预测窗口中的数据不得参与当前轮遗传算法训练，避免未来函数、数据泄露和数据透视问题。

### 4.5 交易信号生成模块

系统应根据遗传算法输出的最优策略，将多个指标信号进行加权融合，并依据交易阈值生成最终交易信号。

信号类型至少包括：

| 信号 | 说明 |
|---|---|
| BUY | 买入或开多 |
| SELL | 卖出或平仓 |
| HOLD | 持仓或观望 |

如系统支持期货扩展，可进一步增加：

| 信号 | 说明 |
|---|---|
| LONG_OPEN | 开多 |
| LONG_CLOSE | 平多 |
| SHORT_OPEN | 开空 |
| SHORT_CLOSE | 平空 |

### 4.6 回测分析模块

#### 4.6.1 回测执行

系统应根据预测阶段生成的交易信号，在历史行情数据上执行回测，模拟资金变化和持仓变化。

回测过程应至少考虑：

- 初始资金。
- 买入和卖出价格。
- 持仓数量。
- 交易手续费。
- 资金净值变化。
- 每笔交易记录。

#### 4.6.2 绩效指标

系统应输出以下回测绩效指标：

| 指标 | 说明 |
|---|---|
| 累计收益率 | 回测期间总收益水平 |
| 年化收益率 | 折算成年化后的收益率 |
| 最大回撤 | 资金曲线最大下跌幅度 |
| 夏普比率 | 单位风险下收益水平 |
| 胜率 | 盈利交易次数占总交易次数比例 |
| 盈亏比 | 平均盈利与平均亏损之比 |
| 交易总次数 | 回测期间所有完整交易次数 |

#### 4.6.3 交易记录

系统应保存并展示逐笔交易记录，内容包括：

- 交易时间。
- 交易方向。
- 交易价格。
- 交易数量。
- 手续费。
- 单笔盈亏。
- 持仓状态。

### 4.7 Web 可视化模块

#### 4.7.1 页面组成

系统 Web 端应至少包含以下页面：

| 页面 | 功能 |
|---|---|
| 首页 | 展示系统简介、功能入口和运行流程 |
| 数据管理页 | 上传 CSV 数据，预览行情数据 |
| 参数配置页 | 配置指标池、遗传算法参数和滚动窗口参数 |
| 回测结果页 | 展示图表、交易记录和绩效指标 |

#### 4.7.2 图表展示

系统应通过 ECharts 等图表组件展示：

- K 线或价格走势图。
- 多技术指标曲线。
- 买入、卖出信号标记。
- 持仓状态变化。
- 资金净值曲线。
- 回撤曲线。
- 年度收益统计图。
- 回撤分布统计图。

#### 4.7.3 参数交互

系统应支持用户在页面中配置以下参数：

- 遗传算法种群规模。
- 迭代次数。
- 交叉概率。
- 变异概率。
- 训练窗口长度。
- 预测窗口长度。
- 初始资金。
- 手续费率。
- 启用的指标类型。

### 4.8 结果对比模块

系统应支持将遗传算法滚动优化策略与固定参数指标策略进行对比，展示二者在收益率、最大回撤、夏普比率、胜率等方面的差异，以验证动态寻优机制的有效性。

## 5. 非功能需求

### 5.1 易用性

- 页面结构应清晰，用户能够按照“上传数据—配置参数—运行回测—查看结果”的流程完成操作。
- 图表和表格应具备清晰标题和字段说明。
- 参数配置项应提供默认值，降低使用门槛。

### 5.2 正确性

- 指标计算结果应符合常见技术指标公式。
- 回测逻辑不得使用未来数据。
- 交易信号生成应与策略参数保持一致。
- 绩效指标计算应准确、可复核。

### 5.3 可扩展性

- 系统应便于新增技术指标。
- 系统应便于新增适应度评价指标。
- 系统应便于扩展数据库存储。
- 系统应便于扩展多标的、多周期和期货多空交易逻辑。

### 5.4 性能要求

- 在单标的日线数据规模下，系统应能在可接受时间内完成遗传算法训练与回测。
- 页面图表展示应保持流畅。
- 对大规模数据或较大种群迭代参数，应给出运行等待提示。

### 5.5 安全性

- 系统应限制上传文件类型，防止非 CSV 文件被误处理。
- 系统应对用户输入参数进行合法性校验。
- 系统不连接真实交易账户，不执行真实下单操作。

### 5.6 可维护性

- 后端代码应按 Controller、Service、Model、Algorithm、Backtest 等模块分层组织。
- 指标计算、遗传算法和回测逻辑应保持相对独立。
- 关键算法和核心业务流程应有必要注释。

## 6. 数据需求

### 6.1 输入数据

系统输入数据主要为 CSV 格式的历史行情数据。示例字段如下：

| date | open | high | low | close | volume |
|---|---:|---:|---:|---:|---:|
| 2024-01-02 | 10.20 | 10.55 | 10.10 | 10.48 | 1200000 |

### 6.2 中间数据

系统运行过程中会产生以下中间数据：

- 技术指标序列。
- 指标信号序列。
- 遗传算法种群数据。
- 每代最优适应度。
- 滚动窗口最优策略。
- 买卖信号序列。

### 6.3 输出数据

系统输出数据包括：

- 回测绩效指标。
- 资金净值曲线数据。
- 回撤曲线数据。
- 交易记录表。
- 买卖点标记数据。
- 年度收益统计数据。

## 7. 约束与假设

### 7.1 开发约束

- 项目周期为 4 周。
- 第 1 周完成需求分析与系统设计。
- 第 2 至第 3 周完成主要编码。
- 第 4 周完成测试、文档整理和演示准备。
- 编程语言采用 Java。
- 系统形态采用 Web 端。

### 7.2 功能范围约束

- 第一版优先支持单个标的的历史数据分析。
- 第一版优先支持 CSV 数据导入。
- 第一版不接入真实交易接口。
- 第一版不以高频交易或实时行情交易为目标。

### 7.3 业务假设

- 用户提供的历史行情数据基本完整。
- 回测交易价格可使用收盘价或下一周期开盘价进行模拟。
- 手续费率由用户配置或采用系统默认值。
- 股票和期货数据在第一版中可使用统一 K 线结构表示。

## 8. 验收标准

系统完成后应满足以下验收条件：

1. 能够通过 Web 页面上传 CSV 历史行情数据。
2. 能够正确解析并展示 K 线数据。
3. 能够计算 MA、MACD、RSI、BOLL 等核心技术指标。
4. 能够构建多指标多参数候选池。
5. 能够运行遗传算法并输出最优策略参数。
6. 能够按照 3 个月训练、1 个月预测的方式执行滚动预测。
7. 能够生成买入、卖出和持仓信号。
8. 能够执行历史回测并输出交易记录。
9. 能够计算累计收益率、年化收益率、最大回撤、夏普比率、胜率、盈亏比等指标。
10. 能够通过图表展示价格走势、技术指标、买卖点、资金曲线和回撤曲线。
11. 系统运行过程中不得使用测试窗口数据参与当前训练窗口优化。
12. 项目文档完整，包括需求文档、设计文档、测试文档和使用说明。

## 11. 风险分析

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 遗传算法运行时间较长 | 页面等待时间过长 | 限制第一版种群规模和迭代次数，提供默认参数 |
| 策略过拟合 | 回测结果虚高 | 使用滚动窗口和综合适应度函数 |
| 数据质量不稳定 | 指标计算异常 | 增加数据校验和异常提示 |
| 指标过多导致开发量增加 | 影响进度 | 第一版优先实现核心指标，其他指标作为扩展 |
| Web 图表数据量较大 | 页面渲染卡顿 | 控制展示数据量，必要时进行采样 |
| 期货逻辑复杂 | 开发难度增加 | 第一版统一使用 K 线回测，期货保证金等作为后续扩展 |

## 12. 总结

本系统以 Java Web 技术为基础，围绕股票与期货量化交易场景，构建多技术指标池，并通过遗传算法进行指标筛选、参数优化、权重分配和交易阈值寻优。系统采用滚动窗口训练与预测机制，严格隔离训练集和测试集，降低未来函数和过拟合风险。最终通过回测分析和 Web 可视化展示，实现从数据导入、智能寻优、交易信号生成到绩效评估的完整流程。

本需求文档将作为后续概要设计、详细设计、编码实现和系统测试的基础依据。
