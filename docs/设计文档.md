# GA_RollTrade_Pred 设计文档

> 基于遗传算法的量化交易策略优化系统

---

## 1. 项目概述

### 1.1 项目简介

**GA_RollTrade_Pred** 是一个基于遗传算法（Genetic Algorithm）的量化交易择时策略优化系统。系统通过滚动窗口训练方式，在历史 OHLCV 数据上自动搜索最优的技术指标组合与参数配置，生成买入/卖出/持有信号，并通过多维度适应度函数评估策略表现。

### 1.2 技术栈

| 层级       | 技术选型                 | 版本             |
| -------- | -------------------- | -------------- |
| 语言       | Java                 | 17             |
| 框架       | Spring Boot          | 3.2.5          |
| 模板引擎     | Thymeleaf            | —              |
| CSV 解析   | Apache Commons CSV   | 1.10.0         |
| 数学计算     | Apache Commons Math3 | 3.6.1          |
| JSON 序列化 | Jackson              | Spring Boot 内置 |
| 前端图表     | ECharts              | 5.5.0          |
| 构建工具     | Maven                | —              |

### 1.3 运行环境

- 服务端口：`8081`
- 文件上传上限：`16MB`
- 无需数据库，数据全内存处理，模型持久化为本地 JSON 文件

### 3.3 遗传算法 (GA)

#### 3.3.1 染色体编码 (Chromosome)

一条染色体 = 一个完整的交易策略，使用 4 维编码：

```
Chromosome
├── mask[N]          (boolean)  指标是否启用          -- 离散
├── paramIndex[N]    (int)      指标参数索引           -- 离散
├── weight[N]        (double)   融合权重 [0.1, 1.5]    -- 连续
├── buyThreshold     (double)   买入阈值 [0.05, 0.8]   -- 连续
└── sellThreshold    (double)   卖出阈值 [-0.8, -0.05] -- 连续
```

**复合信号公式：**

```
compositeScore[bar] = Σ(activeIndicators: weightᵢ × scoreᵢ[bar]) / Σ(weightᵢ)

signal = BUY   if compositeScore >= buyThreshold
         SELL  if compositeScore <= sellThreshold
         HOLD  otherwise
```

#### 3.3.2 进化流程

```
┌────────────────────────────────────────────────────────────┐
│  初始化种群 (populationSize = 80)                            │
│  └── 随机生成染色体 (60% 概率激活每个指标)                      │
└────────────────────────┬───────────────────────────────────┘
                         │
┌────────────────────────▼───────────────────────────────────┐
│  评估所有个体 (FitnessEvaluator)                              │
│  └── 五维适应度评分                                           │
└────────────────────────┬───────────────────────────────────┘
                         │
┌────────────────────────▼───────────────────────────────────┐
│  for generation = 1..120:                                  │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  按适应度降序排列                                      │   │
│  │  ├── 精英保留: 前 2 名直接复制 (免重新评估)              │   │
│  │  └── 剩余 78 个:                                      │   │
│  │      ├── 锦标赛选择 (k=3) → 选择 2 个父代              │   │
│  │      ├── 均匀交叉 (概率 0.78)                          │   │

│  │      └── ensureValid() 修复非法个体                    │   │
```

#### 3.3.3 遗传操作

**交叉（均匀交叉）：**

- 每个基因独立随机选择来自父代 A 或父代 B
- mask、paramIndex、weight 各自独立选择
- buyThreshold、sellThreshold 取两父代平均值

**变异（逐基因）：**

- `mask`：以 mutationRate 概率翻转
- `paramIndex`：以 mutationRate 概率随机化为有效参数索引
- `weight`：以 mutationRate 概率扰动 ±0.3，钳位到 [0.1, 1.5]
- `buyThreshold`：以 mutationRate 概率扰动 ±0.1，钳位到 [0.05, 0.8]
- `sellThreshold`：以 mutationRate 概率扰动 ±0.1，钳位到 [-0.8, -0.05]

**合法性保证 (`ensureValid`)：**

- 至少 1 个指标激活
- paramIndex 钳位到有效范围
- 阈值在合法区间

**固定随机种子：42**

#### 3.3.4 适应度函数 (FitnessEvaluator)

**五维适应度（驱动 GA 训练）：**

```
F = wReturn(0.30) × rScore
  + wDrawdown(0.25) × ddScore
  + wSharpe(0.20)  × shScore
  + wWinRate(0.10) × wrScore
  + wProfitLoss(0.15) × plScore
```

| 维度        | 计算公式                 | 说明                |
| --------- | -------------------- | ----------------- |
| `rScore`  | `softSat(年化收益, 0.5)` | 50% 年化 → 0.5，渐近 1 |
| `ddScore` | `1 - min(最大回撤, 1)`   | 回撤越小越好            |
| `shScore` | `softSat(夏普比率, 2.0)` | 夏普 2.0 → 0.67     |
| `wrScore` | `胜率` (原始值)           | 直接使用 [0, 1]       |
| `plScore` | `softSat(盈亏比, 2.0)`  | 盈亏比 2.0 → 0.5     |

**软饱和函数：** `softSat(x, k) = x / (|x| + k)`

- 保持高值区梯度，避免所有优秀策略拥挤在 ~0.9999 导致选择压力消失

**三层防过拟合机制：**

| 层次  | 机制     | 公式                                    | 说明            |
| --- | ------ | ------------------------------------- | ------------- |
| B1  | 软饱和归一化 | `x/(                                  | x             |
| C1  | 泛化差距惩罚 | `F = 0.5*F(fit) + 0.5*F(val) - λ*     | F(fit)-F(val) |
| C2  | 复杂度正则  | 减去 `complexityPenalty × (活跃指标数/总指标数)` | 偏好简单策略        |

**无交易惩罚：** 如果交易笔数 < 1（全程 HOLD），返回 `-0.5`

**辅助指标（不参与训练）：**

- `directionalAccuracy`：方向预测准确率（可解释性验证）
- `commitmentRate`：非 HOLD 信号占比

### 3.4 滚动窗口训练

#### 3.4.1 设计动机

单次训练容易过拟合特定时间段。滚动窗口训练通过时间序列交叉验证，更真实地评估策略在样本外数据上的泛化能力。

#### 3.4.2 窗口滑动机制

```
时间轴 ─────────────────────────────────────────────────────▶

窗口 1:  [=====训练(3月)=====][==预测(1月)==]
窗口 2:               [=====训练(3月)=====][==预测(1月)==]
窗口 3:                        [=====训练(3月)=====][==预测(1月)==]
...

参数: trainMonths=3, predictMonths=1, stepMonths=1
```

#### 3.4.3 关键设计决策

**严格时序隔离：** 预测月份一定在训练月份之后，杜绝未来信息泄露。

**上下文关联指标计算：** 预测窗口的指标在「训练+预测」拼接数据上计算，再截取预测部分。这避免了短预测窗口内，有回溯期要求的指标（MA、MACD 等）出现冷启动 NaN 问题。

```
训练数据 (3月)          预测数据 (1月)
[=====|====|====]      [====]
                    拼接
[=====|====|====|====]
                    在拼接数据上计算指标
                    └── 前 3 个月已有足够历史，指标稳定
                    截取预测部分
                              [====]  ← 无 NaN
```

**信号去重：** 若 `stepMonths < predictMonths` 导致窗口重叠，同一日期的信号以首次出现为准（`putIfAbsent`）。

**聚合准确率：** 计算跨所有样本外 K 线的方向准确率（不取窗口平均），消除窗口长度不均带来的偏差。

### 3.5 回测引擎

#### 3.5.1 交易规则

- **仅做多 (Long-Only)**：无做空机制
- **全仓进出**：买入信号 → 全部现金转为持仓；卖出信号 → 全部持仓转为现金
- **资金守恒**：`equity = cash + shares × close`
- **手续费**：买入和卖出各收取 `commissionRate × 名义金额`（默认 0.03%）

#### 3.5.2 输出

```
BacktestResult
├── name                   策略名称
├── PerformanceMetrics     绩效指标
│   ├── cumulativeReturn   累计收益率
│   ├── annualReturn       年化收益率
│   ├── maxDrawdown        最大回撤
│   ├── sharpe             夏普比率
│   ├── winRate            胜率
│   ├── profitLossRatio    盈亏比
│   ├── tradeCount         交易次数
│   └── buyHoldReturn      买入持有收益
├── equityCurve[]          权益曲线
├── drawdownCurve[]        回撤曲线
├── trades[]               交易明细
└── signals[]              信号点 (日期, 方向, 价格)
```

#### 3.5.3 绩效计算 (MetricsCalculator)

| 指标   | 公式                                              |
| ---- | ----------------------------------------------- |
| 累计收益 | `equity[n-1] / equity[0] - 1`                   |
| 年化收益 | `(1+totalReturn)^(252/days) - 1`                |
| 最大回撤 | `max{(peak[t] - equity[t]) / peak[t]}`          |
| 夏普比率 | `mean(dailyReturns) / std(dailyReturns) × √252` |
| 胜率   | 盈利平仓笔数 / 总平仓笔数                                  |
| 盈亏比  | 平均盈利 / 平均亏损                                     |
| 买入持有 | `close[n-1] / close[0] - 1`                     |

---

### 3.6 信号生成器

#### 3.6.1 预计算缓存 (3D Cache)

这是系统性能的**核心优化**。对每个滚动窗口，一次性预计算所有指标的所有候选参数在所有 K 线上的得分：

```
double[indicatorIdx][candidateIdx][bar]
     = indicator_i 的参数_j 在 bar_k 的信号得分
```

**收益：** 缓存后的单染色体评估复杂度从 O(I × C × B) 降至 O(A × B)，其中 A 为活跃指标数（通常 3-6），I=9，C 平均约 3，B 为 K 线数。对 80 个染色体 × 120 代，节省的计算量是巨大的。

**`sliceBars(cache, from, to)`：** 为适应度计算中的 fit/val 切分提供零额外计算的子集视图。

#### 3.6.2 信号生成流程

```
indicatorScores[i][j][bar]  (3D Cache)
         │
         ▼
  对每个 Chromosome:
    compositeScore[bar] = Σ(activeIndicators: weightᵢ × scoreᵢ[paramIndexᵢ][bar])
                         / Σ(weightᵢ)
         │
         ▼
    Signal.of(compositeScore[bar], buyThreshold, sellThreshold)
         │     ├── ≥ buyThreshold  → BUY
         │     ├── ≤ sellThreshold → SELL
         │     └── otherwise       → HOLD
         ▼
    List<Signal>  (每个 bar 一个信号)
```

#### 3.6.3 FixedStrategy (固定基准策略)

用于与 GA 优化策略对比：

- 所有 9 个指标启用
- 每个指标使用第一组候选参数 (paramIndex=0)
- 等权重 (weight=1.0)
- 买入阈值 0.3，卖出阈值 -0.3

---

### 3.7 时序标签 (TimingLabel)

#### 3.7.1 设计目的

TimingLabel 提供**方向预测准确率**的可监督验证。不驱动 GA 训练，仅用于模型可解释性评估。

#### 3.7.2 标签生成

```
label[bar] = +1  if futureReturn[bar] >  threshold   (看涨)
             -1  if futureReturn[bar] < -threshold   (看跌)
              0  if |futureReturn[bar]| ≤ threshold  (中性)
            NaN  if bar 是最后 forecastDays 天 (无法计算)
```

其中 `futureReturn[bar] = close[bar+forecastDays] / close[bar] - 1`

#### 3.7.3 自适应阈值

```
if labelThreshold <= 0:
    threshold = 0.5 × std(all_horizon_returns)
else:
    threshold = labelThreshold
```

当 `labelThreshold=0` 时，系统自适应计算 0.5 倍标准差的波动率中性带，避免将所有 K 线标记为 ±1（HOLD 永远判错）。

#### 3.7.4 准确率计算

方向准确率中，HOLD 匹配中性标签(0) 算正确：

```
accuracy = count(predicted_signal == label) / validBars
```

## 9. 关键设计决策

### 9.1 性能：预计算 3D 缓存

**问题：** GA 每个个体评估需要计算 9 个指标的信号，若每次重新计算，120 代 × 80 个体 = 9600 次评估，每次评估都要对所有 K 线跑 9 个指标计算，开销极大。

**方案：** 在每轮滚动窗口开始时一次性预计算所有指标在全部候选参数下的所有 K 线信号，构建 `double[indicator][candidate][bar]` 三维缓存。染色体评估变为 O(active × bars) 的加权求和。

### 9.2 防过拟合：泛化差距惩罚

**问题：** GA 可能在训练数据上找到高适应度但无泛化能力的策略。

**方案：** 将训练窗口对半切分为 fit 和 val 两部分，适应度 = `0.5*F(fit) + 0.5*F(val) - λ*|F(fit)-F(val)|`。该惩罚项直接抑制那些在 fit 上表现优异但在 val 上一落千丈的策略。

### 9.3 信号连续性：上下文关联指标计算

**问题：** 预测窗口通常很短（如 1 个月），若独立计算指标，像 MA(60) 需要前 60 天的数据，短窗口会充满 NaN。

**方案：** 在「训练+预测」拼接数据上计算指标，再截取预测部分。由于训练数据提供了充足的历史，指标在预测段的起点就有稳定值。

### 9.4 模型可复现性：有序指标注册

**问题：** 染色体数组索引依赖指标顺序。若保存和加载时指标顺序不一致，mask[0] 可能指向 MA 或 RSI，导致信号完全错误。

**方案：** IndicatorPool 使用 LinkedHashMap 保持固定注册顺序；TrainedModel 持久化保存 `indicators` 名称列表；加载时按名称列表重建指标集，保证索引对齐。

### 9.5 自适应中性阈值

**问题：** 固定 `threshold=0` 意味着任何微小的方向变动都被打上 ±1 标签，HOLD 信号永远被判错。

**方案：** 当 `labelThreshold ≤ 0` 时，根据实际收益率分布计算 `0.5 * std(horizon_returns)` 作为自适应阈值。高波动标的获得宽中性带，低波动标的获得窄中性带。

### 9.6 软饱和 vs 硬截断

**问题：** 硬截断（如 `min(return, 1.0)`）会导致大量优秀策略全部得到 ~1.0 的适应度，选择压力消失。

**方案：** 使用 `x/(|x|+k)` 软饱和函数，在保持单调性的同时在高值区保留梯度。年化收益 50% 得分 0.5，100% 得分 0.67，正向无限渐近 1。
