# 基于遗传算法的量化策略分析系统项目迭代开发计划

## 1. 文档说明

本文档用于规划“基于遗传算法的量化策略分析系统”的迭代开发过程，明确各阶段开发目标、主要任务、交付成果和验收标准，为项目推进、任务分工、测试验收和文档整理提供依据。

本项目采用短周期迭代开发方式，总体周期为 4 周：

- 第 1 周：需求分析与系统设计。
- 第 2 周：核心算法与数据处理编码。
- 第 3 周：Web 系统整合与回测展示编码。
- 第 4 周：测试、优化、文档整理与项目演示。

## 2. 项目目标

本项目计划实现一套 Java Web 端量化策略分析系统，系统能够导入股票或期货历史 K 线数据，构建多技术指标池，通过遗传算法进行指标筛选、参数优化、权重分配和交易阈值寻优，并采用滚动窗口方式预测买卖时机，最终展示行情数据、交易信号和回测结果。

系统第一版目标是完成一个可运行、可演示、可验证的核心闭环：

1. 上传或读取历史行情 CSV 数据。
2. 计算常用技术指标。
3. 构建技术指标与参数候选池。
4. 使用遗传算法搜索较优策略。
5. 按滚动窗口执行训练与预测。
6. 生成买入、卖出和持仓信号。
7. 执行策略回测。
8. 在 Web 页面展示图表和绩效指标。

## 3. 迭代开发原则

### 3.1 先闭环，后完善

项目优先完成“数据导入—指标计算—遗传算法优化—滚动预测—回测—结果展示”的主流程，确保系统能够完整运行。非核心功能如结果导出、多标的批量回测、数据库存储等作为后续扩展。

### 3.2 先单标的，后多标的

第一版优先支持单个股票或期货品种的历史数据分析，降低系统复杂度。后续可扩展为多标的批量回测和策略对比。

### 3.3 先 CSV，后数据库

第一版采用 CSV 文件作为行情数据输入方式，便于快速开发和测试。若后续时间充足，可增加 MySQL 或 SQLite 数据库存储。

### 3.4 先核心指标，后完整指标池

第一版优先实现 MA、MACD、RSI、BOLL 等核心指标。KDJ、ATR、OBV、CCI 等指标可根据进度逐步扩展。

### 3.5 先可用展示，后精细交互

Web 页面优先满足数据上传、参数配置、回测执行和结果展示。页面美化、筛选交互、导出功能可在核心功能稳定后完善。

## 6. 第 2 周：核心算法迭代

### 6.1 迭代目标

完成系统后端核心算法模块，包括行情数据读取、数据预处理、技术指标计算、指标池构建、遗传算法编码和适应度函数计算。

### 6.2 主要任务

| 序号 | 任务 | 说明 |
|---|---|---|
| 1 | 搭建 Spring Boot 项目骨架 | 创建 Maven 项目，配置基础目录结构 |
| 2 | 实现数据模型 | 定义 KLineData、TradingSignal、TradeRecord、BacktestResult 等类 |
| 3 | 实现 CSV 数据读取 | 解析 date、open、high、low、close、volume 等字段 |
| 4 | 实现数据校验 | 检查字段缺失、数值异常、时间格式错误等问题 |
| 5 | 实现核心技术指标 | 优先实现 MA、MACD、RSI、BOLL |
| 6 | 构建指标参数候选池 | 为不同指标配置多组可选参数 |
| 7 | 设计染色体结构 | 包含指标选择、指标参数、融合权重和交易阈值 |
| 8 | 实现遗传算法基础流程 | 包括初始化、选择、交叉、变异和最优个体保留 |
| 9 | 实现适应度函数 | 综合收益率、最大回撤、夏普比率、胜率和盈亏比 |

## 11. 风险与应对措施

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 遗传算法开发复杂 | 影响核心功能进度 | 先实现基础遗传算法，再逐步优化编码和适应度函数 |
| 指标数量过多 | 开发工作量增加 | 第一版优先实现核心指标，其他指标作为扩展 |
| 回测逻辑容易出错 | 影响结果可信度 | 简化第一版交易规则，重点保证时间顺序和资金计算正确 |
| Web 页面开发耗时 | 影响系统整合 | 使用 Thymeleaf 和 ECharts 快速实现展示 |
| 数据格式不统一 | 上传解析失败 | 提供标准 CSV 模板，增加字段校验 |
| 运行时间过长 | 用户体验下降 | 限制默认种群规模和迭代次数，提供运行提示 |
| 项目周期较短 | 交付风险增加 | 严格控制第一版范围，优先完成主流程 |

## 13. 总结

本项目采用 4 周短周期迭代开发方式，第一周完成需求与设计，第二周完成核心算法，第三周完成系统整合，第四周完成测试与交付。开发过程中应始终围绕主流程闭环推进，优先保证系统能够完整实现数据导入、指标计算、遗传算法优化、滚动预测、回测分析和 Web 可视化展示。后续扩展功能应在核心功能稳定后逐步加入，避免影响项目整体交付。
